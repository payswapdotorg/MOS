## What was implemented

**The /reporting module's Client Decision Room read model** (a PURE LIVE
AGGREGATION — the preferred architecture; migration 031 stays RESERVED and
UNUSED: the decision room owns no durable state, no projection tables,
nothing to migrate or rebuild):

- `src/modules/reporting/public.ts` — the module's public contract,
  extended from the MKT-001 boundary placeholder: the decision-room VIEW
  types (what-happened recaps, learning rationale with the DERIVED
  supersession chain, evidence-quality posture, experiment recaps with the
  RESULTING DECISION surfaced, recommendation presentations, approval
  presentations), the one-method `ReportingModuleApi`
  (`getClientDecisionRoom` — read-only by construction), the
  frozen-matrix-compliant `ReportingModuleDeps` (/goals, /workflows,
  /evidence, /experiments, /learnings + the platform clock; /executions
  and /metrics stay unused allowed directions), and the pure read-model
  derivations re-exported for tests.
- `src/modules/reporting/internal/decision-room-read-model.ts` — the PURE
  composition functions (unit-tested): the evidence-quality grade
  distribution by class (a tally of the /evidence listing — never a
  re-grading), the pending-approval derivation (experiments in
  non-terminal lifecycle states with an UNDECIDED result + workflow
  instances BLOCKED or PAUSED — durable state only, never invented), the
  recommendation derivation (EXACTLY the applicable [derived-status
  'active'] learnings and the CONCLUDED experiments' DECLARED resulting
  decisions — the frozen evidence-and-experimentation contract forbids
  presenting attribution as causal lift, so design type + analysis method
  + result state ride verbatim and no lift field exists anywhere in the
  vocabulary), the what-happened/why/experiments compositions, and the
  full-key status tallies (every frozen status key present, zeros
  included — a stable response shape for the frontend).
- `src/modules/reporting/internal/reporting-module.ts` — the module
  wiring: fetches the Client's authoritative state through the composed
  authorities' PUBLIC CONTRACTS ONLY and composes the view. No db, no ids,
  no write path.

**The route family** `src/api/reporting-decision-room-routes.ts` (the
jobs-visits-routes.ts precedent — one authority, multiple route families):

- `GET /api/reporting/decision-room/:clientId` — the ONLY route: the
  live-aggregated decision-room view. Registered in `routes.ts`; the
  module is wired once in `composition-root.ts` and exposed through
  `application.ts`.
- CLIENT-SCOPED authorization composes the SAME durable-membership
  authority as every client-scoped surface (`requireClientAccess` — the
  decision room serves CLIENT-side users, so the client-scoped check is
  the composed posture, not an agency-scoped platform listing). The
  canonical Client ownership resolves from durable state BEFORE any
  dependent traversal; the path clientId only SELECTS which durable
  ownership chain gets resolved. A foreign/unknown/malformed clientId is
  the UNIFORM 404 (no cross-client oracle); anonymous calls are 401.
- READ-ONLY BY CONSTRUCTION: exactly one GET route; no mutating verb is
  registered in the file (the router 405s POST/PUT/PATCH/DELETE); the
  route reads NO request body and validates NO DTO — authority fields are
  STRUCTURALLY unreachable, not merely rejected; query parameters are
  never read (the scope is server-derived from the authenticated identity
  + durable ownership).
- The workspace enumeration feeding the workflow recaps is SERVER-DERIVED
  at the route layer (`modules.workspaces.listWorkspacesForClient`,
  resolved through canonical Client ownership) and handed to the
  /reporting module as aggregation input — the /reporting matrix line
  holds no /workspaces or /clients direction (the /agents and
  /domain-packs scope-as-data posture).
- The response honestly discloses the read-window bound: the evidence
  quality posture tallies the /evidence authority's bounded public
  listing (newest-first window, server-chosen limit), never an
  authoritative recount of an unbounded append-only ledger.

## Authority boundaries honored

- No new module; no second reporting engine; no write authority: the
  /reporting public contract exposes exactly ONE read method (asserted by
  the static architecture test — no create/update/set/append/record/
  transition/delete/approve/reject/decide verb exists).
- Frozen matrix honored: /reporting ──→ /goals, /workflows, /executions,
  /evidence, /experiments, /metrics, /learnings (five-contract subset
  used; verified by tools/arch-check + the boundary test).
- PostgreSQL is authoritative persistence; the decision room owns NO
  state (pure live aggregation; migration 031 RESERVED and unused —
  asserted by the architecture test).
- Caller-supplied identifiers are never authorization; client isolation
  enforced server-side BEFORE dependent traversal; no secrets in domain
  records; no provider SDKs.

  probe are identical — no decision-room input can alter any authority's
  outcome).

## Known limitations

- The evidence-quality posture is computed over the /evidence authority's
  bounded public listing (default window: newest 500 records) — a
  read-side presentation choice disclosed in the response (`window`
  field), not an authoritative recount of the unbounded ledger.
- The `s3-object-store.test.ts` integration file fails in this sandbox
  for ALL runs including the pristine base SHA: the environment cannot
  download MinIO (no network to dl.min.io). It is unrelated to this Work
  Item (pre-existing, disclosed; the no-false-green rule is honored by
  the test's own provisioning failure).
- MKT-029 (the agency-scoped Agency Command Center family of the same
  /reporting authority) is not merged at this base and is NOT implemented
  here; the module's public entry is ready for that family to register
  against it later.
