## What was implemented

**Migration choice — DISCLOSED: NO MIGRATION (live derivation).** The module
owns NO durable state: there are no `profit_intelligence_*` tables, no
snapshot store and no recompute/converge operation — nothing to rebuild,
because nothing is stored (AC-4's preferred delivery; the /reporting
live-aggregation precedent of MKT-029/030). The expected-migration list is
UNCHANGED; migration 038 was reserved for the MKT-048 sibling per dispatch
correction, and this delivery takes no migration number at all. All figures
are COMPUTED at read time from the authorities' own rows through their
public contracts.

Module `/profit-intelligence` (`public.ts` + `internal/` only — the
reporting house shape):

- `src/modules/profit-intelligence/public.ts` — the frozen contract:
  `PROFIT_INTELLIGENCE_CALCULATION_VERSION = 'pi-calc-v1'` (the frozen
  calculation vocabulary; figures are versioned, never silently restated),
  the exported `PROFIT_INTELLIGENCE_ASSUMPTIONS` set (structured, explicit,
  no hidden constants — every entry ships verbatim in every response),
  `PROFIT_SOURCE_REF_KINDS` (the closed source-reference vocabulary), the
  `ProfitFigure` shape (`value | null` + `currency` + `provenance` +
  `calculationVersion` + `sourceRefs` + `assumptionKeys` +
  `notDerivableReason` — a null value ALWAYS carries an explicit reason,
  never a silent zero), the five derived surfaces (revenue rollup, delivery
  cost breakdown, human capacity, utilization, scope leakage, margin,
  client/service/project contributions), the three view shapes
  (workspace / client / agency), and `ProfitIntelligenceModuleApi` —
  EXACTLY THREE read methods, zero mutation verbs.
- `src/modules/profit-intelligence/internal/profit-derivation.ts` — pure
  derivation functions (no I/O): revenue rollup with
  latest-observation-wins per metric identity (name + dimensions + workspace
  scope; `observedAt` with `recordedAt` tiebreak; superseded rows are
  counted, never summed) with evidence provenance refs; delivery cost over
  the executions attempt ledger (deterministic/extension unit costs — every
  lifecycle state is an attempt that consumed compute) + delivered human
  jobs + usage-telemetry spend; human capacity over field-agents
  authorization-ACTIVE availability windows (normalized weekly minutes);
  utilization (delivered-work minutes over declared capacity, null-with-
  reason at zero capacity); the three scope-leakage indicators (undeclared
  workflow executions, jobs outside declared scope, revenue on
  out-of-scope-but-active goals — with the client-wide-ACTIVE-goal covering
  rule); estimated-vs-realized margin (realized = costing-currency revenue
  slice − observed delivery cost; estimated = ACTIVE goal criteria −
  standing capacity) with the no-FX currency policy (grouping is by
  DECLARED unit, never converted, never mixed); client/service/project
  contribution rows with explicitly disclosed unattributed remainders
  (never silently dropped).

- `src/modules/profit-intelligence/internal/profit-intelligence-module.ts`
  — the live read model: composes the thirteen authority public contracts
  (clients, workspaces, goals, playbooks, workflows, executions,
  deployments, evidence, metrics, jobs, field-agents, ai-runtime,
  integrations — the frozen dependency-matrix line), derives every figure
  through the pure functions and returns the views. Canonical ownership
  resolves FIRST (unknown/tombstoned Client or Workspace → the uniform 404
  upstream, before any dependent traversal). Zero mutation methods; zero
  owned state (architecture-lock-v1.5 #6).

Routes (`src/api/profit-intelligence-routes.ts`, registered additively in
`src/api/routes.ts`; module exposed additively in `src/api/application.ts`
and `src/composition-root.ts`) — EXACTLY THREE GETs, read-only by
construction:

- `GET /api/profit-intelligence/:agencyId` — the agency portfolio rollup
  (per-client contribution rows, service/project contributions, capacity,
  utilization, leakage totals, portfolio margins).
- `GET /api/profit-intelligence/:agencyId/clients/:clientId` — the
  client's full derived surface.
- `GET /api/profit-intelligence/:agencyId/clients/:clientId/workspaces/:workspaceId`
  — the workspace-scoped slice.

The scope is SERVER-DERIVED on every read: the authenticated identity + the
durable agency membership (suspended member 403, anonymous 401 fail-closed)
+ live-client/workspace state; the aggregation inputs (the agency's live
clients, its ACTIVE human_agent membership users) are enumerated from
durable state, never accepted from the caller. Tenant identity can never
arrive via DTO — no request body, no DTO validation, no query parameters
(proven statically). The uniform 404 covers foreign ≡ unknown ≡ malformed
agencies, clients and workspaces (no cross-tenant existence oracle);
authorization is re-resolved FRESH in the execute step of every route.

## Boundaries

- DERIVED, NEVER AUTHORITATIVE: the module exposes ZERO mutation methods
  over ANY authority; it cannot mutate contracts, billing or any
  financial/accounting state. Proven statically: no mutation verb in the
  route file; the public contract exposes exactly three read methods; the
  module internals contain ZERO SQL (all authority access is through the
  composed public contracts); no migration is owned, so the
  expected-migration list is unchanged.
- READ-ONLY BY CONSTRUCTION: GET routes only; mutating verbs are 405 at the
  router; after every read/probe the authoritative rows are byte-identical
  (proven in the integration battery).
- Figures are COMPUTED, not stored truths: every count is cross-checked
  against DIRECT SQL ground truth over the authority tables in the
  integration tests; a live-follow test mutates through the REAL authority
  APIs and observes the analytics follow on the very next read; the same
  inputs + the same calculation version derive byte-identical figures
  (pinning), and a version bump would be disclosed in the response
  (`calculationVersion` on every figure + `calculation` disclosure on every
  view).
