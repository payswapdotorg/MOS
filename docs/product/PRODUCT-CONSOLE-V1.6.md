# MOS Product Console — v1.6 Growth Autonomy Contract

Status: Product implementation contract
Architecture authority: v1.6 frozen documents

## 1. Outcome-first home

Primary actions:

- Grow an audience
- Market a product
- Find a product to sell
- Generate leads
- Generate revenue

Secondary:
- Continue a mission
- Today / agency operations
- Attention
- Connections

The existing v1.5 Command Center remains as Today / Operations rather than the only front door.

## 2. Mission setup

One progressive flow collects:
- outcome;
- target;
- optional product URL;
- optional authorized source repository/workspace;
- optional store;
- connected social platforms/accounts;
- fixed platform portfolio or Choose for me;
- source/content preferences;
- budget/quota;
- autonomy mode;
- optional human-treatment budget.

## 3. Mission workspace

Expose:
Target / Progress / Now / Next / Why / Hypothesis / Experiment / Platforms / Health / Content / Rights / Transformation / Measurement / Decision / Learning / Blockers.

The user should understand in one screen:
What are we trying to achieve? What is MOS doing? Why? What happens next?

## 4. Creator growth

Research -> Evidence -> Hypothesis -> Experiment -> Rights -> Transform -> Publish -> Measure -> Analyze -> Learn.

## 5. Product marketing

Start with:
Paste a product URL.

Show what MOS observed before asking for approval to operate.

## 6. Commerce discovery

Start with:
I do not know what to sell.

Show:
Market -> Product candidate -> Evidence -> Content test -> Viability -> Listing -> Traffic -> Order -> Margin -> Learning.

## 7. Connections

Expose:
YouTube, Instagram, Facebook Pages, TikTok, X, product/source integrations, store, notifications.

Every connection shows capabilities, permissions, expiry/revocation and limitations.

## 8. Content / rights / transformation

Every candidate shows source, evidence basis, rights state, transformation plan, destination and publication state.

## 9. Platform health

Use descriptive states only:
healthy, degraded, distribution anomaly suspected, publishing restricted, authorization expired, quota constrained, automation/inauthenticity risk suspected, human review required.

## 10. Scientific trace

Question -> Research -> Evidence -> Hypothesis -> Experiment -> Publication -> Measurement -> Analysis -> Decision -> Learning.

Keep observed, inferred and causal states visually distinct.

## 11. Human amplification

Human work is an optional experiment treatment.

Show availability, budget, offer state, disclosure, usage rights and measured outcomes.

No mission depends on accepted human work.

## 12. Existing v1.5 surfaces

Preserve:
Today, Clients, Attention, Profit Intelligence, Human Work, Apps, Administration.

Client Workspace remains:
Overview, Goals, Strategy, Deployments, Workflows, Evidence, Decisions, Learning, Memory.

## 13. ShareNet-inspired design language

Use:
- warm neutral background;
- graphite text;
- restrained green/teal healthy accent;
- amber warning;
- red error;
- generous whitespace;
- minimal decorative chrome;
- subtle state transitions;
- one primary action;
- progressive disclosure;
- diagnostics secondary to outcomes.
