## 3. Migration 059 — the fences

- CHECK-fenced vocabularies on every enumerated column (the scenario/run/
  candidate/capability/calibration statuses, the failure reasons, the
  modes, the factuality labels, the regimes, the external-reference kinds).
- The composite `lab_scenarios_pk (scenario_id, scenario_version)` — the
  version chain (corrections append new rows under the same id); runs and
  candidates bind EXACT versions through composite FKs.
- Guarded immutable UPDATE triggers on every artifact (identity columns
  never change; only lifecycle status/bookkeeping advance); DELETE
  rejected everywhere (append-only history).
- The run transition fence: `lab_run_event_consistent()` validates the
  frozen edge set AND that `from_status` matches the run's CURRENT durable
  state under the row lock; the paired CAS update advances `version` by
  exactly one.
- Scope fences: every cross-reference trigger rejects cross-client links
  (run↔scenario, candidate↔scenario, evaluation↔candidate+run,
  calibration↔candidate+run).
- The §23 cap probe surface: partial index on active statuses per client.

## 5. Disclosures

- **No HTTP routes yet** — LAB-001 is the contract layer; the console/API
  surfaces arrive with LAB-014/016/017 and UX-008+ (the console bridge
  composes the module through the composition root, in-process).
- **The run "engine" is deliberately absent** — the module records and
  transitions runs; the simulator that DRIVES runs is LAB-005 (worker A).
  The §23 budget caps are RECORDED and enforced at the lifecycle level
  (the honest exceeded → failed(budget_exceeded) transition); the
  step-count enforcement point lives in the simulator loop that calls
  `failRun(reason='budget_exceeded')`.
- **The WorldModelVersion is a citation shape only** — the version
  REGISTRY belongs to LAB-008's ensemble layer; runs cite opaque version
  strings so LAB-005/006/007 can bind before that registry exists.
- **Scenario correction semantics** (disclosed judgment call): a corrected
  scenario starts the new version as DRAFT — the frozen-at-run gate
  applies per version (a corrected scenario must be re-activated before
  new runs bind it). Existing runs keep their pinned versions regardless.
- **The evaluation summary shape** (reward + uncertainty interval +
  ensemble agreement + OOD + seed robustness + factuality + metrics) is
  the frozen §13/§20 envelope; the LAB-008/009 evaluators fill it as data.
- **A hardening fix rides this delivery**: src/entrypoints/api.ts now
  registers the SIGTERM/SIGINT graceful-shutdown handlers BEFORE the
  api.started line is emitted. The added startup work of this delivery
  (the /lab import chain + migration 059 verification) made a previously
  theoretical race deterministically hittable: a test watcher that kills
  on the started line could land the signal between the log write and
  the handler registration, killing the control plane by raw signal
  (exit null, no api.stopping). Registration-before-announcement closes
  the window outright (deployment-topology AC-01 passes deterministically).
