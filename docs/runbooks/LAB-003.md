## 1. What shipped

The `/lab-features` module — the versioned feature-extraction authority
every later Lab consumer (LAB-004 Idea Graph, LAB-005 simulator, the
TL's corpus advance integration) consumes BY REFERENCE:

| Surface | What shipped |
| --- | --- |
| Feature set | The closed, versioned §5 feature vocabulary — exactly **27 feature keys** grouped by the 4 modalities (`lab-featureset-v1`): the text/audio/visual/metadata embeddings, the title/description/hashtag semantics, the thumbnail/opening-frame and visual composition, the hook/narrative/pacing/scene-transition structure, the topic/subtopic/entity/problem/claim/curiosity-gap semantics, the speaking rate and emotional trajectory, the information density, the CTA structure, the language, the duration, the novelty/reuse risk, the product references, the creator baseline, the age-normalized performance, the performance velocity, the engagement, and the retention/impression features — every key pinned to its modality group and its §5 source phrase in `LAB_FEATURE_KEYS` |
| Value discipline | The NEVER-FABRICATE value map: every bundle accounts for EXACTLY the closed 27-key set; every value is either `derived` (with its encoder identity + a concrete representation) or `unavailable` (with its closed reason from the 7-value unavailable vocabulary, NO representation) — enforced by `assertValidLabFeatureValueMap` and the `derived+unavailable = 27` CHECK fence |
| Deterministic identity | Two pure functions: the input digest (SHA-256 over the canonical JSON — DEEP sorted keys — of the complete extraction input) and the identity digest (SHA-256 over the reference identity fields + the feature-set version + the extractor identity/version + the input digest); `UNIQUE (client_id, identity_digest)` makes the deterministic identity the idempotence fence (re-extraction under the same versions is the honest `skipped/already_extracted` outcome citing the existing bundle) |
| Version chain | The append-only per-reference bundle chain: `UNIQUE (client_id, reference_id, bundle_version)` — a changed feature-set/extractor/input version is a NEW bundle version, never an in-place rewrite; bundles reject UPDATE and DELETE outright |
| Source linkage | Every bundle carries the FULL citation data as recorded data (referenceId, corpus binding, provider, providerContentId, canonicalUrl, the metadata digest, the availability observed at extraction) — there is deliberately NO foreign key into any `/lab`, `/lab-corpus` or v1.6 authority table |
| Ephemeral media access | The optional media-access grant (the closed availability + posture vocabularies) with the fail-closed §4 gate: ONLY `(available_permitted, reference_gated)` opens a path — `unknown`/`provider_unavailable`/`withdrawn` fail `media_unavailable`, `available_rights_unclear` and any `metadata_only` posture fail `rights_not_permitted`, all BEFORE any bytes are requested; granted bytes ride an IN-MEMORY HANDLE through the extraction call only (the replaceable `LabMediaFetchPort`) — there is NO bytea/binary column anywhere in migration 065 |
| Extraction port | The replaceable `LabFeatureExtractor` port + the honest first-party implementation: metadata-grade features (duration, language, engagement-family where present in the recorded snapshot) derive deterministically from the recorded snapshot; embedding-grade/media-grade features record their honest `unavailable` state with the closed reason — never fabricated |
| Batch extraction | The bounded batch (1–100 citations): a run row born `running`, exactly ONE outcome record per item (`extracted` / `failed` + its closed 7-value failure reason / `skipped` + its closed skip reason), the completion advance computing the summary counts SQL-side from the item outcome rows (never asserted separately — the status-conditional CHECK fence pins the arithmetic at `completed`) |
| Tenant isolation | Every row is client-scoped (+ optional workspace anchor) with the uniform NotFound on foreign scope (no existence oracle); the DB-level scope-consistency triggers reject cross-tenant bundle/item injection (§22) |

## 3. Migration 065 — the fences

- Three own tables ONLY: `lab_feature_batch_runs`,
  `lab_feature_bundles`, `lab_feature_batch_items` — CHECK-fenced
  closed vocabularies on every enumerated column (run lifecycle, item
  outcome, the 7-value failure vocabulary, the skip vocabulary, the
  availability/posture/fetch-status echoes, the feature-value states,
  the modality subset `<@` fence, the pinned
  `'lab-features-contract-v1'` / `'lab-featureset-v1'` versions).
- The FK anchors are EXACTLY the tenant tables (agencies, clients,
  workspaces) + same-module rows (bundle → creating run; item → run;
  item → bundle) — NO FK into any `/lab`, `/lab-corpus` or v1.6
  authority table.
- The deterministic-identity fences: `identity_digest`/`input_digest`
  64-hex CHECKs, `UNIQUE (client_id, identity_digest)` (idempotence)
  and `UNIQUE (client_id, reference_id, bundle_version)` (the
  append-only chain).
- The 27-key feature accounting fence:
  `derived_feature_count + unavailable_feature_count = 27`.
- The status-conditional summary-counts fence: a run is born
  `running` with all counts honestly zero; at `completed` the
  SQL-computed `extracted+failed+skipped = item_count` arithmetic is
  CHECK-pinned.
- Guarded triggers: bundles and item outcomes are append-only
  OUTRIGHT (UPDATE and DELETE rejected); the run guard enforces
  identity/scope/config immutability + the single `running →
  completed` advance (no reopen); scope-consistency triggers reject
  cross-tenant bundle and item injection.
- NO bytea/binary/payload column anywhere (the §4
  temporary-media-bytes rule applied structurally — media bytes are
  inexpressible as durable state).

## 5. Disclosures

- **THE CORPUS ADVANCE SEAM IS NOT IMPLEMENTED** (by mandate): the
  `/lab-corpus` `feature_bundle_version` 'pending' → bundle-version
  advance is the LAB-002 module's OWN guarded seam, owned by the Tech
  Lead's LAB-004/005 integration. This module produces everything
  that integration needs — the citable bundle reference
  (`labFeaturesBundleReference`) and the per-reference chain read
  (`listBundles`) — and the integration battery proves a REAL
  `/lab-corpus` reference extracted here keeps its 'pending' state.
- **The first-party extractor is deliberately honest, not magic**:
  metadata-grade features derive deterministically from the recorded
  citation snapshot; embedding-grade and media-grade features record
  their honest `unavailable` state with the closed reason
  (`encoder_unavailable` / `media_unavailable` / the
  history/corpus-grade reasons). Real encoder + provider adapters
  arrive with the corpus backfills; the ports are the seams.
- **The media-fetch port is the pending first-party port**: a
  validated grant reaches it and gets the honest `pending` outcome
  (no provider media adapter is wired); test doubles in the
  integration battery prove the granted + refused paths through the
  same port contract.
- **Batch-gate semantics (disclosed judgment call)**: the batch input
  gate validates STRUCTURE only (the bounded 1–100 item list, item
  objects, the configuration shape); a semantically invalid citation
  or grant is the honest per-item `failed/invalid_input` outcome
  INSIDE the run — exactly one outcome per item, never a whole-batch
  rejection that would leave sibling items unrecorded.
- **The gate order follows the §4 chain** (access before decode): the
  media gate runs BEFORE the modality gate — the item's own access
  posture is decided first, the extractor's capability to serve a
  required modality second.
- **The spec registration is the granted worker exception**: the
  delivery appends the `/lab-features` registration paragraph to
  `spec/architecture.md` §6 (the MKT-066 platform-health precedent)
  and registers the module in the composition root +
  `ApplicationModules` + the arch-check expected set; NO checker
  provision entry was added (the provision mechanism is structurally
  for spec-pending modules only). No matrix row was needed —
  `/lab-features` consumes no other module.
- **Migration numbering**: 065 is pre-assigned (062 reserved for the
  parallel MKT-072 worker, 064 held by the in-flight STUDIO-001);
  the sibling boundary tests re-pin the canonical migration-list tail
  positions mechanically (the MKT-070/LAB-002/LAB-011 precedent).
