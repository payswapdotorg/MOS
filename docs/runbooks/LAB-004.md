## 4. The disclosed deterministic formulas

- **Novelty** (`lab-idea-novelty-v1`):
  `novelty(candidate, observedSameKind) = 1 − max Jaccard(tokens(candidate.descriptor), tokens(n.descriptor))`
  over the observed nodes of the same primitive kind (node_id
  ascending — the deterministic comparison order; the tie-break picks
  the smallest node id); `1` when the observed set is empty;
  `tokens = the deduplicated lowercase alphanumeric token set of the
  descriptor`; the score rounded to 4 decimals (the numeric(5,4)
  column discipline). Measured against OBSERVED nodes ONLY.
- **Clustering** (`lab-idea-clustering-v1`): the clusterable space =
  the observed + derived nodes (generated/combined are candidates,
  not corpus evidence — they never cluster); within each primitive
  kind, the undirected similarity graph where two nodes are similar
  iff `Jaccard ≥ 0.5`; clusters = the connected components (union by
  the lexicographically smaller root — the root is the component
  minimum); `clusterKey = '<kind>#<the component's smallest node
  id>'`; `clusterSize` recorded on every member row. Same node set +
  same version → the same clusters (the pure function; deterministic
  input ordering by node id).
- **Decomposition identity**: SHA-256 over the canonical JSON (DEEP
  sorted keys — the LAB-003 discipline) of (the cited bundle identity
  fields, the idea-set version, the decomposer identity+version, the
  input digest); the input digest is SHA-256 over the canonical JSON
  of the complete citation (identity fields AND the structural
  feature-map echo).
- **Lineage construction**: the creating operation's new edges (each
  input → the output, the operation's relation, ordered by input
  position) first, then each input's own recorded lineage steps
  (input order, deduplicated by (fromNodeId, toNodeId, relation),
  renumbered 1..N); exceeding 64 steps fails closed.

## 5. Ports — what is REAL vs deterministic-first-party vs PENDING

- **The module owns** (NOT the ports): the operation records, the
  output node's origin class, the recorded lineage, the lineage
  edges and the novelty measurement.
- **The decomposer port** (`LabIdeaDecomposer`, replaceable): the
  first-party implementation is honest — it derives ONLY the
  primitives the cited feature values honestly support (metadata
  grade: packaging ← title/description/hashtag semantics,
  timing_context ← duration, audio_treatment ← speaking rate;
  encoder grade: idea ← topics, problem/claim ← problem_claim, hook
  ← pattern, narrative ← structure, visual_treatment ← composition,
  cta ← cta — these derive NOTHING while the cited features record
  their honest unavailable states; the same table lights up when a
  real encoder is wired) and asserts ZERO semantic edges (a
  supports/contradicts judgment is semantic — never invented; the
  port CONTRACT carries the intra-decomposition edge surface for a
  real semantic decomposer).
- **The generator port** (`LabIdeaGeneratorPort`, replaceable):
  derive/recombine/fill_gap are REAL first-party DETERMINISTIC
  STRUCTURAL operations (the shared-token abstraction, the ordered
  composition, the recorded gap — explicitly labeled '(structural)',
  never semantic invention); mutate/analogy/invert — the open-ended
  generative kinds — ship the honest PENDING refusal (the operation
  fails closed BEFORE any row exists: nothing recorded, nothing
  fabricated) until a real generator is wired through the same port.

## 7. Disclosed judgment calls

1. **The evidence filter is `['observed_source']` ONLY** (the
   strictest reading of §6: a derived abstraction is derived data,
   not source evidence — the observed/derived/generated/combined
   distinction implies derived ≠ observed).
2. **Decompositions produce observed_source nodes ONLY**; every
   derived_abstraction arrives through a `derive` operation (the
   smallest architecture-consistent split of the creation paths; the
   §6 supports list names the graph operations).
3. **The clustering space is observed + derived** (the
   evidence-bearing space); generated/combined nodes are candidates,
   not corpus evidence, and never join clusters.
4. **The module path is atomic by construction**: the decomposer /
   generator port runs BEFORE any row exists and the write lands in
   ONE transaction (born running → the tail rows → the completion
   advance) — a crash rolls the whole artifact back (no partial
   state ever commits). The born-running lifecycle still exists at
   the DB for the future long-running decomposition path (a real
   semantic decomposer driving resumable decompositions) and the
   guard's single-advance semantics are DB-proven in the integration
   battery.
5. **The one-run-per-(client, clustering-version) discipline**: an
   unchanged node set re-runs idempotently (the pure-function
   comparison); a changed node set under the same version is the
   honest conflict — re-clustering requires a new version (the
   version-bump is the documented path, never a rewrite).
6. **The listDecompositions chain read resolves the bundle id from
   the citable reference** ('<bundleId>#v<n>' → the per-cited-bundle
   version chain); the retrieveNodes cited-bundle filter matches the
   node's versioned citation echo exactly (the node's provenance is
   the exact bundle version it was decomposed from).
7. **The pending refusal maps to InvalidRequestError** (422,
   retryable: false) — the honest synchronous refusal with the
   pending reason; nothing is recorded.
8. **Sibling boundary-test re-pins**: the ~21 mechanical re-pins
   (366 migration tail-position shifts + 66 new-066-tail pairings +
   the module/spec counts 56→57 / 55→56 + the composition-map
   adjacency string + the canonical infra-adapters migration list +
   the cross-platform structure-total regex) follow the
   LAB-011/LAB-003 worker precedent; the TL resolves the merge with
   the parallel LAB-013/UX-010 siblings.
