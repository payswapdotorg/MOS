## 3. Migration 071 — the fences

- Seven own tables ONLY: `lab_simulator_world_configs`,
  `lab_simulator_seeds`, `lab_simulator_runs`,
  `lab_simulator_run_steps`,
  `lab_simulator_observable_snapshots`,
  `lab_simulator_ensembles`,
  `lab_simulator_ensemble_members` — CHECK-fenced closed
  vocabularies on every enumerated column (the pinned
  `'lab-simulator-contract-v1'` / `'lab-worldmodel-v1'` /
  `'lab-sim-engine-v1'` / `'lab-simulator-splitmix64'` /
  `'lab-sim-rng-v1'` versions; the
  `'declared_world_model_assumptions'` modeling basis on every
  configuration row; the `'simulated_model_output'` factuality label
  on every run row; the closed outcome-metric vocabulary; the u64
  seed shape + numeric bound; the 64-hex digest shapes; the bounded
  step budget / member counts).
- The FK anchors are EXACTLY the tenant tables (agencies, clients,
  workspaces) + same-module rows (seed → config via the composite
  (config_id, config_version) FK; run → seed + config + the optional
  self-replay target; step → run; snapshot → run; member →
  ensemble + run + config) — NO FK into /lab, /lab-features,
  /lab-ideas or ANY v1.6 authority table (the content-universe
  citations are OPAQUE recorded data).
- THE REPLAY FENCES: a normal run carries no replay columns; a
  replay carries the original + the recorded proof — the
  NULL-SAFE biconditional `CHECK ((NOT deterministic_replay AND
  replay_of_run_id IS NULL AND replay_verified IS NULL) OR
  (deterministic_replay AND replay_of_run_id IS NOT NULL AND
  replay_verified IS TRUE))` (the IS TRUE form — a bare `= true`
  comparison would PASS a CHECK on NULL; the fence must reject,
  never shrug).
- The status-conditional summary fences: a run is born 'running'
  with an honestly-zero summary; at 'completed' `step_count =
  step_budget` and the trajectory digest is present. An ensemble is
  born 'running' with an honestly-zero uncertainty summary; at
  'completed' `min ≤ mean ≤ max`.
- The append-only discipline: configurations, seeds, steps,
  observable snapshots and ensemble members reject UPDATE and DELETE
  outright; runs and ensembles advance running → completed exactly
  once under the guarded triggers (identity/scope/citation/plan/
  universe immutable; the summary values change only at the advance,
  SQL-computed from the tail rows).

## 4. The disclosed deterministic formulas

- **The RNG** (`lab-sim-rng-v1`): splitmix64 over the master seed;
  per-label streams derived as `splitmix64(masterSeed XOR
  FNV-1a64(label))` (the FNV-1a 64 prime 0x100000001b3, the standard
  vectors pinned in the unit battery); `nextFloat = Number(u64) /
  2^64` (the deterministic IEEE conversion). The five labels, in the
  engine's fixed consumption order: user-sessions → competition →
  trends → ranking → interactions.
- **The interaction loop** (per step, the fixed RNG order): the
  session counts `round(expected × (1 + 0.2·z))` (z = the Irwin-Hall
  triple); the trend update `clamp01(persistence·prior + (1 −
  persistence)·seasonal + volatility·(2u − 1))` with the seasonal
  baseline `baselineInterest × (1 + amplitude·sin(2πt/period))`; the
  competitor posts (count = the declared rate; index/topic/quality
  drawn — the topic trend-weighted with a 0.001 epsilon); the
  candidate pre-score `quality × 0.5^(age/halfLife) × (1 + trend)`,
  top-`candidatePoolSize` by score DESC (itemId ASC tie-break); the
  exposure curve `share(p) = topWeight × p^(−decayPower)`
  normalized, plus the exploration promotion (one drawn tail
  candidate promoted per step when the drawn uniform is under the
  exploration rate); the response probabilities
  `p_view = clamp01(baseView + affinity·0.25 + noveltyBias·novelty −
  min(1, fatigue)·responsePenalty + (quality − 0.5)·
  qualitySensitivity·0.5)`, `p_engage = clamp01(engagePerView × (0.5 +
  quality))`, `p_share = clamp01(sharePerEngage × (0.5 + 0.5·
  novelty))`, `p_click = clamp01(viewToClick + affinity·0.25)`; the
  stochastic counts `round(expected + z·sqrt(capacity·p·(1−p)))`
  clamped to the capacity (the aggregate binomial approximation — 15
  uniforms consumed per (segment, account pool item), always);
  fatigue accumulates `incrementPerExposure` per account pool item of
  the topic then decays `(1 − decayPerStep)`; novelty `= 1/(1 +
  exposure count)`.
- **The competitor live list** is bounded to the most recent
  `max(64, 8 × candidatePoolSize)` posts (the bounded-world memory —
  DISCLOSED); the account live items are never pruned (≤ 512 plan
  entries).
- **The digests**: the configuration digest (SHA-256 over the
  canonical JSON of knobs + the pinned versions), the seed digest
  (masterSeed + configDigest), the step digest (the canonical step
  content), the observable digest (the canonical observable
  projection), the trajectory digest (SHA-256 over the ordered
  step-digest chain joined by newlines). Every digested float is
  rounded to 4 decimals FIRST (the deterministic
  numeric-serialization discipline).
- **The ensemble agreement**: `agreement = majority-side-of-the-mean
  count / member count` (≥ 0.5 by construction, 1 = full agreement),
  `disagreement = 1 − agreement`, over the declared outcome metric
  (default `'conversions'` — business-outcome-first).

## 5. What is REAL vs declared-assumption vs NOT HERE (by design)

- **The simulator core is REAL and deterministic** — the pure engine
  (`world-core.ts`) consumes no clock, no I/O, no ambient state; the
  module's orchestration is atomic-by-construction (the run + steps
  + snapshots land in ONE transaction with the single completion
  advance — a crash rolls the whole artifact back).
- **The ranking/exposure parameters are DECLARED MODELING
  ASSUMPTIONS** — every configuration row is CHECK-fenced with the
  `'declared_world_model_assumptions'` basis, every recorded
  exposure decision carries the marker, and the
  `LAB_SIMULATOR_RANKING_DISCLOSURE` string ships on the public
  surface: they are NOT claims about any provider's actual algorithm.
  NO hidden moderation/reputation/internal-ranking model of any real
  platform is modeled as a factual claim — the simulator targets
  OBSERVABLE behavior only (the §8 rule, made structural in the
  observable-snapshot table).
- **NOT HERE (the later Lab layers)**: the calibrated user/creator
  dynamics (LAB-006), the time machine + information lag (LAB-007),
  the TRAINED response models + OOD scores (LAB-008 — this module's
  ensembles sample the KERNEL's declared configuration space; the
  model-version ensembles arrive there), the off-policy evaluation
  (LAB-009), the sequential RL (LAB-010), the reward function

## 7. Disclosed judgment calls

1. **The run's write is atomic-by-construction** (the LAB-004
   judgment call #4 precedent): the pure engine computes the whole
   trajectory in memory, then the run born 'running' → the steps +
   snapshots → the single completion advance land in ONE transaction.
   The born-running lifecycle exists at the DB for the future
   durable-worker path (§23: long-running simulation through the
   worker infrastructure, never synchronous requests).
2. **The replay verification happens BEFORE any row exists** — a
   mismatch throws the honest ConflictError with nothing recorded;
   the persisted `replay_verified = true` is therefore always true
   on completed replays (the DB fence pins exactly that — no
   unverified replay row is expressible). The mismatch path is
   structurally unreachable while the engine version is pinned; it
   is the fail-closed backstop for engine drift across future
   versions (a replay under a changed engine would mismatch and
   refuse, honestly).
3. **The observable/hidden split is enforced in the ENGINE, not just
   the DB**: the observable projection is built from a closed
   literal shape (the boundary test asserts the construction site —
   no fatigue/trend/score internals can enter it); the step records
   (the audit trail) carry the model internals clearly labeled as
   the world model's own declared mechanics, never provider facts.
4. **The trajectory digest is module-computed from the recorded
   step digests** (PostgreSQL has no pgcrypto-free sha256): it is a
   pure function of the recorded `step_digest` column values — the
   reproducibility test re-derives it independently. The SUMMARY
   totals are SQL-computed (the house discipline).
5. **The config digest idempotence spans chains**: an identical knob
   set returns the existing configuration regardless of the
   requested chain — identical world models are the same
   configuration (the LAB-003/004 identity discipline). A version
   bump with UNCHANGED knobs hits the digest fence and returns the
   existing row (a no-op rewrite is inexpressible).
6. **The content-universe topic/quality are the CALLER's declared
   simulation attributes** of the cited /lab-features bundle or
   /lab-ideas node — recorded data, never claims about the cited
   artifact's actual platform performance (the citation is opaque;
   the module reads NO /lab-features or /lab-ideas table).
7. **The stochastic counts ride the aggregate binomial
   approximation** (the Irwin-Hall z over the binomial sd, clamped
   to the capacity) — the population is simulated at the
   SEGMENT-AGGREGATE level, not per individual user agent (the
   bounded-kernel reading of §9; the calibrated per-user response
   models are LAB-006/008).
8. **The competitor post volume is the declared exact rate per
   step** (the count is deterministic; the index/topic/quality are
   stochastic) and the competitor live list is bounded to the most
   recent `max(64, 8 × candidatePoolSize)` posts (the bounded-world
   memory) — both DISCLOSED declared assumptions of the kernel.
9. **The step-budget cap is 1000** and the plan entries cap at 512
   (the §23 bounded-run discipline; the ensemble members cap at 32,
   the config space at 8 — the §13 minimum is 2).
10. **The ensemble outcome metric is declared per ensemble** from the
    closed §12 reward-input vocabulary (default `'conversions'` —
    business-outcome-first); the agreement formula is the majority
    side of the mean (≥ 0.5 by construction). The interval is
    [min, max] over the members — the honest uncertainty record of
    the KERNEL's declared configuration space; the trained-model
    uncertainty intervals are LAB-008.
11. **The spec registration paragraph is appended at the END of §6**
