## 1. What this delivery is

MKT-054 introduces the **persistent goal-pursuit CONTROLLER** of v1.6: a
per-mission, restart-safe controller that selects **bounded next
experiments/actions** from a versioned strategy space and **delegates ALL
physical work to the existing Workflow/Execution authorities**
(architecture-v1.6.md §13: "Growth Operator is a persistent controller, not a
workflow engine.").

What it is NOT (the bounded scope):

- **NO second execution engine** (the cardinal rule, rule 17). The module
  contains no job pickup, no dispatch/queue submit, no sandbox leasing, no
  worker pool, no retry orchestration and no execution-lifecycle mutation.
  The delegated execution is created through the /executions public command
  (born `created`) and the RUNTIME PLANE owns its lifecycle; the execution
  port on this module exposes ONLY create + read, so the operator
  structurally cannot express an execution transition.
- **NO human-marketplace dependency** (rules 43/44/45; matrix rules 11/12).
  No /field-agents, /jobs or human-agent surface is imported anywhere in the
  module; the human-amplification arm is a declared, considered-and-recorded
  OPTIONAL strategy input with ZERO defaults, never a blocker and never a
  fabricated result.
- **NO mission-authority transfer** (rule 16 / boundary rule 3). The operator
  advances mission state ONLY through the MKT-053 module's own public
  `setGrowthMissionStatus` command, exactly like any other caller.

## 2. The controller contract (public entry `src/modules/growth-operator/public.ts`)

| Surface | Member | Notes |
| --- | --- | --- |
| init | `initializeController({missionId, pursuitWorkspaceId, budget?}, provenance)` | ONE controller per mission (UNIQUE); born `running`; the mission is activated through its own command; the pursuit scope is canonically resolved (unknown/disabled/cross-agency workspace → the uniform 404) |
| tick | `pursueMission({missionId}, provenance)` | THE pursuit cycle: reconcile → observe → replan → gate → delegate. Idempotent; safe to call repeatedly, concurrently and after any restart |
| lifecycle | `pauseController` / `resumeController` / `terminateControllerByPolicy` | REQUIRED reasons; CAS; the mission record mirrors through its own command |
| read | `getController` / `getControllerDetail` / `listControllerDecisions` / `listControllerEvents` / `listControllerPlanSteps` | the honest read-back surfaces the later MKT-070/072 planners and MKT-074 console consume |

### The tick, in order

1. **Terminal** → the honest no-op (nothing runs after a terminal state).
2. **Paused / blocked** → the honest no-op (the outcome carries the state).
3. **Reconcile the mission state**: a mission that became terminal out-of-band
   is recorded as the controller's own `terminated_by_policy`
   (`mission_already_terminal`); a mission paused out-of-band makes the
   operator DEFER (the controller pauses — the conservative, honest choice).
4. **Reconcile the delegated work** (restart-safety): `planned` steps (a
   crash window) are re-driven to completion convergently; `dispatched`
   steps are read through the authorities' public read surfaces, and work
   that reached a terminal state on the workflow authority is OBSERVED — an
   /evidence `observation` record citing the instance + execution, the step
   moves to `observed`, an `observation` decision is appended.
5. **The achievement check** (before the in-flight gate): ALL actively-mapped
   goals achieved (live through the mission module's own goal views — the
   measurable anchor) → the honest `achieved` terminal.
6. **The in-flight gate**: no replan while `dispatched` steps ≥
   `maxInFlightSteps`.
7. **The budget/quota check**: `maxDelegatedSteps` reached without
   achievement → the truthful `exhausted` terminal (never a fabricated
   success).
8. **The idempotent replan**: the evidence snapshot digest over the
   observable world → the deterministic plan-step idempotency key → a
   replay converges (the DB UNIQUE fence); a changed world yields a NEW
   append-only step.
9. **The gate walk** (only an explicit allow delegates): a
   `deny_pending_human_action` blocks truthfully; a plain `deny` skips to
   the next family; no allow at all terminates honestly
   (`policy_denied_no_alternative`).
10. **The delegation** — all through the EXISTING authorities (see §4).

## 3. The state machine (frozen, go-vocab-v1)

```text
                ┌─────────────────────────────────────────────────────┐
                │                                                     │
   (init) ──▶ running ──pause──▶ paused ──resume──▶ running            │
                │                    │                                 │
                │                    └──terminate──▶ terminated_by_policy
                │                                                     │
                ├──block:genuine gate──▶ blocked_pending_human_action─┤
                │                            │                        │
                │                            ├──resume──▶ running     │
                │                            └──abandon──▶ terminated_by_policy
                │
                ├──achieve──▶ achieved (terminal, frozen)
                ├──exhaust──▶ exhausted (terminal, frozen)
                └──terminate─▶ terminated_by_policy (terminal, frozen)
```

- Terminal states have NO outgoing transitions (code, module checks and the
  migration-050 transition-pair trigger agree).
- `achieved` is reachable ONLY from `running` (the honest-state rule: "The
  controller never silently converts a block into success.").
- `blocked_pending_human_action` requires a REQUIRED reason + a GENUINE gate
  kind (`rights` | `policy` | `capability` — CHECK-fenced in storage). It is
  the ONLY truthful human blocker; zero budget / no creators / declined or
  expired offers are NOT blockers (they are recorded strategy inputs).
- The honest terminal causes (recorded on the terminal event + the mission
  transition): `goal_achieved`, `delegation_budget_exhausted`,
  `mission_already_terminal`, `no_delegable_treatment`,
  `policy_denied_no_alternative`, `blocked_gate_abandoned`,
  `operator_requested_stop`.

### The mission-state composition (MKT-053 stays the authority)

| Controller | Mission (through the mission authority's own command) |
| --- | --- |
| running | active |
| paused | paused |
| blocked (waiting) | UNCHANGED — stays in its current non-terminal state |
| achieved | achieved |
| exhausted | budget_quota_exhausted |
| terminated_by_policy | policy_constrained (or the honest alternative: `blocked_pending_human_action` when the block was abandoned, `blocked_by_unavailable_capability`, `failed_after_bounded_recovery`; from a paused mission only `stopped_by_user` is legal in the frozen mission machine — the reason carries the honest cause) |

**Disclosed decision — the resumable blocked wait lives in the controller
state.** The MKT-053 mission machine records `blocked_pending_human_action`
as a TERMINAL state (its runbook: "a future unblock/resume-after-human-action
semantics for MKT-054 would need an Architect-clarified state extension (or
successor missions); MKT-053 deliberately does not invent one"). This
delivery honors that freeze: while the controller WAITS for the human action
the mission record stays non-terminal and the controller state + decision
records + the (future) notification plane surface the block; when the
controller terminates while blocked, the mission receives the honest
terminal `blocked_pending_human_action` transition.

## 4. Delegation semantics (the cardinal rule, operationally)

Every delegated step creates, through the EXISTING authorities' public
commands:

1. **The experiment** — /experiments `createExperiment` (the bounded next
   experiment; the hypothesis embeds the step tag for crash-window
   convergence).
2. **The strategic decision** — /decisions `createDecision` (the §8
   idempotency key is step-derived: the durable convergence anchor).
3. **The pursuit workflow container** — /workflows `createWorkflow`, once
   per mission (deterministic name `growth-operator-pursuit-<missionId>` —
   find-or-create).
4. **The step definition** — /workflows `createWorkflowDefinition` (a
   minimal valid §4 graph: one `function` entry staging node → one
   `experiment` node carrying the treatment → one `terminal` outcome
   recorder; the node ids are step-derived — the find-or-create anchor),
   activated through the authority's own `setWorkflowDefinitionStatus`
   (draft → review → active).
5. **The instance** — /workflows `createWorkflowInstance` (pinned to the
   definition; find-or-create by the pin).
6. **The instance lifecycle** — /workflows `transitionWorkflowInstance`
   (draft → ready → running; the idempotency keys are step-derived). The
   operator REQUESTS the work; it never executes it.
7. **The execution** — /executions `createExecution` (taskLink =
   workflow-node coordinates; executionKind `deterministic`; runtimeClass
   `pooled-worker`; the §8 logical key is step-derived — the hard
   no-double-dispatch guarantee). Born `created`; the RUNTIME PLANE (the
   existing worker/dispatch machinery outside this module) owns the
   lifecycle. The operator only ever READS it afterwards.

Observations flow back through /evidence `appendEvidence` (class
`observation`, quality C — a defensible system observation of the delegated
authorities' terminal verdicts; the content carries the instance/execution
statuses verbatim).

### Restart-safety (crash-window convergence)

The plan step row is the write-ahead record (inserted `planned` BEFORE any
authority call); every obtained reference is recorded back on the step row
immediately. On recovery the reconcile re-drives a `planned` step:

- the experiment converges by its step-tagged hypothesis (the client
  experiment listing);
- the decision converges by its §8 idempotency key;
- the workflow converges by its deterministic name;
- the definition converges by its step-derived node id;
- the instance converges by its pinned definition;
- the instance transitions converge by their idempotency keys;
- the execution converges by its §8 idempotency key.

The only theoretical residue of the crash window is an orphan identity
object (e.g. a draft definition) when the crash lands between the authority
create and the reference fill — inert, never dispatched, disclosed here.

## 5. The strategy space (go-strategy-v1 — pure, deterministic, versioned)

The bounded treatment families: `owned_channel_publish`,
`content_variant_test`, `channel_reallocation`, `measurement_enrichment`
(the always-delegable NON-HUMAN set) and `human_amplification` (the declared
OPTIONAL arm — considered on every replan, NEVER delegated by MKT-054: the
existing /jobs authority seam is the later optional MKT-076..078 wave).

Selection scoring: the objective-family affinity rank (a frozen per-family
map over the MKT-053 §3 vocabulary) + a bounded exploration bonus (every
family gets its first steps) + the honest outcome memory (a succeeded family
is favored; a failed one cools down). Tie-break: score DESC, family ASC. No
time factors, no randomness — the same inputs always produce the same plan.
The idempotency key derives from the strategy version + the
evidence-snapshot digest + the step sequence: replays and restarts converge
to ONE step (DB UNIQUE per mission), and a changed world yields a NEW
append-only step. A plan change is always a RECORDED deliberate change (the
inputs changed — new evidence/learnings/goal statuses/budget — and the
decision record cites them).

## 6. Zero-human policy (frozen, tested)

- The controller's budget policy carries `humanAmplificationBudget` and
  `humanAmplificationEligibleCapacity` — **both ZERO by default** (DB
  defaults included). The zero-human state is the normal default, never an
  error.
- Every replan records the human consideration
  (`consideredHuman: {eligible, budget, eligibleCapacity, reason}`) on the
  plan step and the decision — the zero-human state is a RECORDED strategy
  input, never an absence.
- The arm is eligible only when BOTH funded (budget > 0) AND capacity > 0.
  In the current tree the capacity is zero BY CONSTRUCTION (no
  human-growth marketplace capability exists at this base).
- Even when funded-with-capacity (and the objective family favors humans —
  the arm tops the scoring), the MKT-054 controller CANNOT delegate human
  work: the selection records the honest reallocation to the best
  NON-HUMAN family (`reallocatedFromHuman` + the rationale). No human
  result is ever fabricated; unavailability is never a failure.
- Negative tests pin all of this at three levels: pure (every family ×
  every budget/capacity combination continues non-human), integration
  (the default end-to-end path with the recorded consideration and no
  human artifacts) and architecture (no human-marketplace import/table).

## 12. Honest disclosures & limitations

- **The platform-health seam (MKT-066)**: the frozen v1.6 matrix row for
  /growth-operator additionally lists /platform-health, which does not exist
  at this base (a later Worker B Work Item). The registered row is the
  currently-satisfiable subset (the /product-intelligence MKT-069 precedent

  therefore does not yet consume distribution-anomaly signals.
- **Later planner integrations (MKT-070/072)**: the /playbooks and
  /deployments directions are matrix-listed allowances the MVP loop
  deliberately does not yet exercise — the product-marketing and
  commerce-discovery planners compose them; the operator's decision records
  (kind, rationale, evidence refs, consideredHuman, candidates trail) are
  shaped to be their inputs.
- **The rights gate is a seam, not the real authority**: MKT-063 (Worker B,
  parallel) lands /content-rights; until then the gate composes the REAL
  /policies engine, and the simulated rights gate exists only as the
  disclosed `AppOptions.growthOperatorGate` test double (the
  provider-boundary-double precedent).
- **The human arm is not delegable in MKT-054** (by design — the /jobs seam
  is the optional MKT-076..078 wave); when funded-with-capacity it is
  honestly reallocated to non-human treatments, never executed.
- **The crash-window orphan**: a crash between an authority create and its
  reference fill can leave an inert identity object (e.g. a draft
  definition); convergence prevents duplicates and the orphan is never
  dispatched.
- **Budget model scope**: maxInFlightSteps (1..5), maxDelegatedSteps (null =
  unlimited), the human-amplification inputs. The §17 finer budgets
  (platform API quota, compute/AI/storage cost, paid-media, commerce test
  budget) arrive with their authorities (MKT-056+ adapters, MKT-066,
  MKT-071+); the controller's budget fields are the honest seams.
- **No notification wiring yet**: the blocked/blocked-terminal states are
  recorded on the controller + decisions + events; surfacing them through
  the /notification-delivery plane (MKT-068) is not on this module's matrix
  row and belongs to the console/notification composition (MKT-074 lane).
- **No scheduler**: the tick is driven by external callers (service
  principal / future worker / console action). The controller is a durable
  state machine, not a timer — no second scheduler is introduced.
- **The old broken node_modules symlink**: the base carried a committed
  absolute symlink `node_modules -> /home/z/mos-verify/node_modules` (a
  prior verification-session artifact pointing outside the repo). This
  delivery removes it (it breaks `bun install` for every consumer).
