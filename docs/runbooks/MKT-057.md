## 8. Honest limitations and disclosures

1. **The media-byte transfer of the resumable upload is NOT wired.**
   submitPublish performs the documented metadata INITIATION (a real
   documented API call establishing the upload session); the PUT of
   asset BYTES to the session URI awaits the content-asset resolution
   wiring — the frozen /social-accounts matrix row carries NO
   /content-assets direction, so the mediaAssets ride the request as
   opaque references (the adapter passes the declared media-kind hint
   as `x-upload-content-type`). A metadata-only session does not
   complete a real video upload on the live API; the full lifecycle
   (upload → processing → published/rejected/failed) is modeled and
   polled, and the completion path is proven against the faithful
   double. The distribution planner (MKT-065) owns the asset
   resolution seam. NO durable state was added for this (the 056
   discipline holds — no new migration).
2. **Successful calls report rateLimit: null** — the documented YouTube
   API exposes no remaining-quota headers (the quota is project-side
   accounting). The observable quota signals surface ONLY on the
   documented 403 quota/rate failures (Retry-After where the provider
   sends one — the double's `rateLimitExceeded` does, its daily
   `quotaExceeded` deliberately does not). Fabricating remaining-units
   would be dishonest; this is the documented surface.
3. **The initiation 400 (invalid metadata) maps to 'restricted'** — a
   disclosed judgment call with two disclosed reasons: the frozen
   seven-code taxonomy has no malformed-request code, AND the frozen
   migration-050 CHECK (`failed ⇒ failure_code NOT NULL`) forbids the
   null-code processed-rejection row on the ATTEMPT ledger (an
   ok-path `failed` submission with providerFailureReason but no
   taxonomy code cannot be stored — the adapter-contract docstring's
   "processed-but-failed" providerFailureReason carrier is the ASYNC
   post-processing path, the status-poll observations, where the frozen
   OBSERVATION table allows the null code — that path IS implemented
   and proven). The provider's verbatim envelope rides the failure
   message. If the Architect prefers a dedicated taxonomy code for
   provider-validated request refusals, that is an Architecture Change
   Request (not opportunistically changed here).
4. **Other unclassifiable 4xx map to 'restricted'** (the same disclosed
   judgment — non-retryable provider-side refusal; the verbatim
   envelope rides the message). 5xx and transport
   refused/timeout/oversized map to provider-unavailable (retryable —
   the derived retryability).
5. **The null analytics window defaults to the wide documented-legal
   window** (startDate 2005-01-01 → endDate 2099-12-31 — the aggregate
   lifetime window): startDate/endDate are REQUIRED Analytics report
   parameters and the frozen read input allows null windows; the
   adapter never invents metric points (an empty report yields NO
   observations).
6. **readContentAnalytics issues one report request per content id**
   (the safe documented `filters=video==<id>` form) — up to 20 requests
   per normalized read (the frozen input bound).
7. **The conformance run exercises the IN-MEMORY double** (the work
   item's "a faithful in-memory double modeled on the documented API"),
   NOT the real HTTP adapter — the arch-check TEST_MODULE_INTERNAL_IMPORT
   rule forbids tests from importing module-internal files, so the real
   adapter is only constructible by the composition root. The REAL
   adapter is proven by the SEPARATE end-to-end battery (the
   production-composed instance over the REAL FetchHttpCall transport
   against the loopback documented-API double). Both proofs are green;
   neither substitutes for live googleapis.com calls (not possible from
   the sandbox, deliberately not attempted).
8. **The combined provider double serves the OAuth plane and the API
   plane on ONE loopback origin** (a test-infrastructure choice so the
   connection's `providerConfig.apiBaseUrl` — which the conformance
   suite hardcodes to the provider double's URL — points the real
   adapter at the double). Production Google hosts are separate
   (accounts.google.com vs www.googleapis.com vs
   youtubeanalytics.googleapis.com); the adapter's DEFAULT bases are the
   documented public hosts and the providerConfig keys are the
   documented deployment override surface.
9. **The conformance helper extension is test-only and defaulted** —
   `fullScopes`/`readOnlyScopes` default to the reference vocabulary;
   the MKT-056 reference suite runs (full + partial) are byte-for-byte
   unaffected (re-run green below).
10. **Boundary-tail re-pins (the wave disclosure):** the MKT-056
    boundary test's two assertions pinned to the pre-057 world — the
    adapter-subtree residents (`['adapter-contract.ts']` → `+
    'youtube'`) and the composition seam
    (`socialAdapters: options.socialPlatformAdapters ?? []` → the
    first-party registration + the seam override). Both re-pins are
    additive MKT-057 truths written against this base; the Tech Lead
