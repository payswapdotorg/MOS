## 1. Contract summary

### 1.1 What this module IS

The **rights authority** behind explicit asset-level rights state and
the publication gate other modules (MKT-065 cross-platform
distribution, later) call BEFORE publishing:

| Surface | Contract |
| --- | --- |
| `content_rights_records` (migration 051) | The CLIENT-SCOPED **asset-level rights records**: the current rights state bound to an OPAQUE content-asset reference (the MKT-064 seam — see §5), with the REQUIRED `/evidence`-anchored **source provenance**, licence evidence + label (required the moment the state claims a licence basis — the payload-shape CHECK), the `valid_until` **expiry horizon** (evaluated FAIL-CLOSED at gate time), the one-record-per-(client, asset ref) fence, and the born-`unknown` current-state pointer that moves ONLY along the frozen transition table. |
| `content_rights_events` | The fully **append-only state-transition tail**: one immutable row per transition (from_state, to_state, event_kind, the REQUIRED reason, server-derived provenance) with the **frozen transition-table CHECK** — `cleared` is reachable ONLY from `review` via `human_clearance` with the clearance row. History is recorded events, never in-place mutation. |
| `content_rights_clearances` | The **HUMAN CLEARANCE records** — the ONLY review → cleared path: the ACTOR IDENTITY of the clearing human, the REQUIRED rationale, and the optional `/evidence` reference for supporting review evidence (**fair-use reasoning rides HERE** — evidence for review, never an automatic legal guarantee, never an auto-clear). |
| `content_rights_permissions` | The **destination-platform permission scope**: what the source's licence permits on which destination platforms — one immutable row per recording (each with its REQUIRED `/evidence` reference); the NEWEST row per (record, platform) is effective (scope changes are NEW rows; the full tail stays auditable). |
| `content_rights_lineage_links` | The **immutable ingredient lineage links**: one link per (client, composite ref, ingredient ref), no self-links, fully append-only. A composition resolves its rights as the **CONJUNCTION** of its ingredients. |
| `evaluatePublicationGate` | **THE PUBLICATION GATE** (fail-closed by construction): allow / review_required / blocked WITH reasons, the per-ingredient breakdown and the destination-policy decision id. See §3. |

### 1.2 The frozen rights state vocabulary (cr-vocab-v1)

The MKT-063 acceptance list VERBATIM plus the explicit initial state:

```
owned | license | platform_permitted | cleared | review | blocked | unknown
```

- `unknown` is the state every record is BORN in — the initial
  undetermined posture (the dispatch's "unknown/undetermined";
  architecture-v1.6.md §9 names the concept "unclear" — same posture,
  the backlog acceptance vocabulary is the frozen authority here).
- The frozen **transition table** (CHECK-fenced in migration 051,
  mirrored by the pure `isLegalContentRightsTransition`):

| from | to | kind |
| --- | --- | --- |
| unknown | owned / license / platform_permitted / review / blocked | `determination` |
| review | cleared | `human_clearance` (clearance row REQUIRED) |
| review | blocked | `review_denial` |
| owned / license / platform_permitted / cleared | review | `contestation` |
| owned / license / platform_permitted / cleared | blocked | `revocation` |
| blocked | review | `re_review_request` |

There is deliberately NO row into `cleared` except
`review --human_clearance--> cleared`, and no determination resolves
anything but `unknown` — the fail-closed human-action spine. State
transitions are recorded events (the append-only tail); the record's
current-state column moves only along the same fenced pairs, in the
SAME transaction as its event row (CAS: the live state must equal the
event's from_state).

### 1.3 The module API (src/modules/content-rights/public.ts)

- **`registerContentRights`** — creates the rights record for one
  content-asset reference (born `unknown`; one record per (client,
  asset ref) — the unique fence makes re-registration the honest 409;
  a re-registered asset is a NEW asset version, which is a NEW ref —
  the MKT-064 immutability discipline). Source provenance evidence is
  REQUIRED and resolved canonically through `/evidence` BEFORE any
  write (uniform 404 for unknown/foreign — the DB same-Client trigger
  is the backstop).
- **`recordRightsTransition`** — appends the immutable event row and
  moves the record's state in ONE transaction (SELECT ... FOR UPDATE
  CAS; the losing side of a race is the honest ConflictError, never a
  torn history). `human_clearance` requires the clearance payload
  (rationale REQUIRED; the clearing actor is the SERVER-DERIVED
  provenance actor — a human identity at the route surface).
- **`recordPlatformPermission`** — appends one destination-platform
  permission row (permitted | not_permitted; REQUIRED evidence
  reference resolved through `/evidence`).
- **`recordLineageLink`** — records one immutable composition fact
  (duplicate pairs are the honest 409; links are client-scoped).
- **`evaluatePublicationGate`** — THE gate (§3).
- **Reads:** `getRightsRecord`, `getRightsRecordForAsset`,
  `resolveRightsOwnership` (the route-layer uniform-404 input),
  `listRightsRecordsForClient`, `listRightsEvents`,
  `listPlatformPermissions`, `listClearances`, `listLineageLinks`.
- **Pure core (exported for tests + future callers):**
  `isLegalContentRightsTransition`, `conjunctionOfGateOutcomes`,
  `evaluateContentRightsState`, `publicationPolicyKey`, the full guard

### 1.5 Boundaries (what this module deliberately does NOT do)

- **NO publication authority** (boundary rule 4): the gate blocks or
  refers to review; it never publishes, dispatches, schedules or
  acknowledges a publication. MKT-065 owns distribution execution.
- **NO silent approval of unclear rights**: only an explicit recorded
  human clearance (actor identity + rationale) moves review → cleared;
  `unknown` requires a determination first; NO code path from
  unknown/review to allow bypasses the recorded human-action events
  (proven by the unit illegal-pair matrix + the DB CHECKs).
- **NO content-asset storage** (MKT-064): assets are known ONLY by
  opaque grammar-fenced refs — no artifact bytes, no object-store
  addresses, no transformation state.
- **NO legal advice**: states are operational publication gates, not
  legal determinations; fair-use reasoning attaches as clearance review
  evidence.
- **NO platform adapter knowledge**: destination platforms are opaque
  grammar-fenced keys (`^[a-z][a-z0-9_-]{0,31}$`) carried as data —
  platform-specific rules live behind the adapter plane (Worker A).

## 3. The publication gate contract (the MKT-063 heart)

`evaluatePublicationGate({ agencyId, clientId, assetRef,
destinationPlatform }, provenance)` →
`{ outcome, reasons[], composite, ingredientEvaluations[],
policyDecisionId, evaluatedAt, vocabularyVersion }` with
`outcome ∈ allow | review_required | blocked`.

### 3.1 Outcome mapping (fail-closed throughout)

| Condition | Outcome | Reason code |
| --- | --- | --- |
| No rights record for the asset in this client | **blocked** | `no_rights_record` (an absent evaluation is never an allow) |
| Recorded state `blocked` | **blocked** | `rights_state_blocked` |
| `valid_until` has passed (whatever the state) | **blocked** | `licence_expired` |
| Recorded state `unknown` | **review_required** | `rights_state_unknown` (NEVER an auto-approve) |
| Recorded state `review` | **review_required** | `rights_state_review` |
| Recorded state `owned` | **allow** | `allowed_owned` |
| Recorded state `cleared` | **allow** | `allowed_human_clearance` |
| `license` / `platform_permitted` + destination row `permitted` | **allow** | `allowed_license_scope` / `allowed_platform_permission` |
| `license` / `platform_permitted` + destination row `not_permitted` | **blocked** | `destination_not_permitted` |
| `license` / `platform_permitted` + NO destination row | **review_required** | `destination_permission_unspecified` (unspecified scope fails closed to human review) |
| Destination policy non-allow (deny OR unknown/no-active-policy) | **blocked** | `policy_denied` |
| Composite, any ingredient blocked / absent | **blocked** | `ingredient_blocked` / `ingredient_no_rights_record` |
| Composite, any ingredient unclear | **review_required** | `ingredient_rights_unclear` |
| Composite-kind record with NO lineage links | **blocked** | `lineage_missing` (sourceLineageRequired) |
| Lineage cycle | **blocked** | `lineage_cycle` |
| Lineage depth > 16 | **blocked** | `lineage_depth_exceeded` |

BOTH non-allow outcomes are fail-closed — the gate never permits on
uncertainty. `review_required` is the one honest surface rights become a
`blocked_pending_human_action` source for their consumers (MKT-065
distribution, mission policy); `blocked` is the definite negative.

### 3.2 The conjunction rule (ingredient lineage)

A composite's outcome = conjunction of its OWN evaluation and every
unique ingredient's (recursively, cycle-guarded by the traversal
ancestry, depth-bounded at 16):

- any **blocked** or **absent** ingredient → the composite is blocked;
- else any **unclear** (unknown/review/unspecified-scope) ingredient →
  the composite is review_required;
- only all-allow (+ own allow) allows.

Padding, compilations and composites carry their own rights because
every linked ingredient resolves its OWN record in the composite's
client — an ingredient with no resolvable record fails the composite
closed. Cross-Client composition has no resolvable rights here
(links + records are client-scoped) — disclosed as the honest posture.

### 3.3 Expiry and revocation semantics

- **Expiry** is data (`valid_until`) evaluated FAIL-CLOSED at gate time:
  a passed horizon BLOCKS the evaluation whatever the recorded state;
  the recorded state itself is never silently rewritten by time. (A
  licence renewal is a NEW asset version = NEW ref = NEW record — the
  MKT-064 immutability discipline; within one reference the recorded
  licence facts are immutable. Disclosed.)
- **Revocation** is a recorded transition event (`revocation` →
  blocked) — auditable in the append-only tail, never an erasure.

### 3.4 The destination policy gate (destinationPolicyGateRequired)

EVERY gate evaluation runs the `/policies` engine (network dimension,
key `content.rights.publication.<platform>`) — the decision id rides the
result, and only an explicit **allow** permits; deny AND unknown
(including no-active-policy) both BLOCK. This implements the frozen
manifest's hard rule "destinationPolicyGateRequired" and the AGENTS.md
v1.6 rule "Cross-platform redistribution requires explicit
rights/provenance clearance for the source asset and
destination-policy compatibility."

2. **The MKT-065 seam:** cross-platform distribution (the gate's
   primary future consumer) does not exist yet. The gate exposes the
   frozen contract (`evaluatePublicationGate` + reason codes +
   `review_required` as the `blocked_pending_human_action` signal) that
   MKT-065 will call before publishing; no distribution, publication or
   per-account capability logic lives here.
3. **Gate semantics decisions (disclosed, frozen in cr-vocab-v1):**
   - "Fail-closed: absent or incomplete rights evaluation = blocked,
     never allowed" is implemented as: **absent record → blocked**
     (`no_rights_record`); **incomplete** evaluations (unknown state,
     unspecified destination scope, unclear ingredients) →
     **review_required** — both outcomes are non-allow (fail-closed);
     review_required is the human-action-pending surface, blocked the
     definite negative.
   - `cleared` bypasses the destination permission-scope check (the
     human clearance is an explicit recorded decision that resolves the
     rights question) but NOT the `/policies` destination gate.
   - `valid_until` applies to the RECORD whatever the state (an
     operator would not set a horizon on owned content; expiry fails
     closed everywhere).
   - Licence facts (evidence ref, label, valid_until) are immutable per
     record: a licence-basis determination requires the licence
     evidence recorded at registration (the payload-shape CHECK);
     licence renewal is a new asset version = new ref = new record.
4. **Cross-Client composition fails closed:** lineage links and records
   are client-scoped; an ingredient that resolves to no record in the
   composite's client blocks the composite. Multi-client composition
