### 1.1 What this module IS

(the analysis layer reads experiment records through their public
contract only and is never a second experiment engine):

| Surface | Contract |
| --- | --- |
| `experiment_analysis_records` (migration 054) | The APPEND-ONLY ANALYSIS RECORDS: the full §12 computed set as durable DATA — treatment/comparison effects (per-arm means, the effect estimate with its Welch standard error), uncertainty (the normal-approximation interval at the declared level), sample sizes (per arm), the observation window consumed, the sequential-analysis state (interim index, the Bonferroni per-look level, cumulative alpha spent, boundary crossing, the continue flag), confounders and limitations (declared inputs MERGED with deterministic derived entries), the practical effect threshold (recorded value + source), the recommended next allocation, and the EXACT INPUT SNAPSHOT the computation consumed with its canonical deterministic digest. | `experiment_allocation_recommendations` (migration 054) | The APPEND-ONLY ADAPTIVE-ALLOCATION RECOMMENDATIONS: the bounded exploration/exploitation shares over declared strategy-variant arms (treatment / comparison / strategy_variant / human_treatment kinds), with the EXPLORATION FLOOR AS RECORDED DATA (value + source — never a hardcoded magic number), the zero-capacity arms recorded WITH their exclusion reason (the human-growth invariant: a human-treatment arm with zero capacity never blocks, crashes or invalidates the non-human allocation), the recorded human-arm consideration (never an absence), and the FULL deterministic input snapshot + digest so re-running the allocator on the same inputs reproduces the same decision. | `computeTwoArmEffect` / `classifyAnalysisOutcome` / `computeSequentialState` / `mergeConfounders` / `mergeLimitations` | The PURE deterministic statistics core ('two_sample_means_v1' v1.0.0): per-arm means, the mean difference with its Welch standard error, the fixed-z interval (0.9 / 0.95 / 0.99 — the frozen z table), the total outcome classification against the recorded practical threshold, the Bonferroni sequential state over the recorded 5-look budget, and the declared+derived confounder/limitation merges. Zero I/O, zero randomness, zero clock reads. |

### 1.2 The frozen vocabularies (ea-vocab-v1)

All CHECK-fenced in migration 054:

```
outcome:        effect_positive | effect_negative | effect_negligible | inconclusive | insufficient_observations
allocation:     shift_toward_treatment | shift_toward_comparison | hold_balanced | conclude_and_adopt
arm kinds:      treatment | comparison | strategy_variant | human_treatment
floor sources:  declared_input | module_default_v1
method:         two_sample_means_v1 (single-value CHECK)
version:        ea-vocab-v1
```

The outcome classification is TOTAL over the interval states:
interval entirely above +t → `effect_positive`; entirely below −t →
`effect_negative` (the honest negative); bounded within [−t, +t] →
`effect_negligible` (a precise null); straddling any boundary →
`inconclusive` (the honest unknown); either arm below the declared
minimum → `insufficient_observations` (the empty window is still a
first-class record). A NEGATIVE or INCONCLUSIVE result is a valid
scientific outcome — a first-class recorded value, never an error, never
coerced to success.

## 4. Analysis/allocation proof points (the dispatch's named proofs)

### 4.1 How negative/inconclusive results are preserved

Three fences, all test-proven: (1) the VOCABULARY —
`effect_negative`, `effect_negligible`, `inconclusive` and
`insufficient_observations` are first-class outcome values in code (the
closed type union) and in the database (the CHECK constraint contains
them verbatim); the classification is total and never maps a
non-positive state to a positive one. (2) The DATABASE — both tables
reject UPDATE and DELETE outright (`*_append_only()` BEFORE UPDATE OR
DELETE triggers), so not even server code can rewrite a recorded
outcome; the trigger's rejection message states the preservation rule
explicitly. (3) The TAIL — a re-analysis is a NEW record (a new
interim look in the sequential state); the old record stays
byte-identical and readable forever. Integration NAMED (a) proves all
three end-to-end on real PostgreSQL.

### 4.2 How allocation is reproducible

Every recommendation records its FULL input snapshot (the experiment
anchor + status, the optional analysis linkage, the declared arms with
capacity/sample/mean/variance in canonical armKey order, the resolved
exploration floor + its source, the fixed scoring level, the strategy
version) and its canonical deterministic digest. The allocator is pure
(zero I/O, zero randomness, stable armKey ordering — declaration order
never influences the result). Reproducibility is proven both ways:
recording the same inputs twice yields identical digests and identical
shares, and re-running the exported pure allocator over a RECORDED
snapshot reproduces the recorded decision exactly (and its digest).

### 4.3 How the allocator stays valid at zero human capacity

A declared arm with `capacity: 0` — the human-treatment arm included —
is EXCLUDED from the share computation and RECORDED in
`zeroCapacityArms` with its kind and an explicit reason carrying the
invariant ("never blocks, crashes or invalidates non-human
allocation"); the human-arm consideration is a recorded field (never an
absence), and the remaining arms receive exactly the allocation they
would have received had the human arm never been declared (proven by
the shares-equality assertion). When EVERY arm is at zero capacity the
honest all-zero state is recorded (empty shares, every exclusion
recorded) — never an error. The module's `/experiments` consumption is
unchanged by human capacity (the experiment anchor is read-only
identity/design), so there is no path by which human absence could
block the analysis layer.

## 5. Honest disclosures & known limitations

1. **The normal-approximation interval:** the two-sample method uses
   the Welch standard error with the fixed-z normal-approximation
   interval (not the exact t-distribution) and the sequential state
   uses a Bonferroni per-look level with a piecewise-linear
   interpolation over the fixed support table for intermediate levels.
   Both are disclosed, deterministic, versioned approximations
   ('two_sample_means_v1' v1.0.0) — adequate for the v1.6 analysis
   layer's bounded-signal purposes, honestly recorded as data. A future
   method version can tighten them; the recorded analyses stay
   byte-exact.
2. **The bounded /metrics read:** the module consumes the Client's
   observation ledger through `listMetricObservationsForClient` (the
   house 500-row bound — the profit-intelligence precedent). A window
   whose matching observations exceed the read produces the derived
   `derived:observation_read_truncated` limitation on the record (the
   honest caveat) rather than a silent truncation; long windows should
   be narrowed or the cadence raised. A purpose-built windowed metrics
   query would be a change to the `/metrics` public contract (a
   separate Work Item — not taken here).
3. **The arm-split convention:** the analysis consumes observations
   carrying the reserved `arm` dimension with values `treatment` /
   `comparison` (the house experiment arm-label convention; an
   experiment declaring `arm` inside its primary-metric identity is
   rejected fail-closed by the create guard). The convention is
   documented, grammar-checked and deterministic; a different labeling
   convention would be a future method extension.
4. **Shared files touched (the parallel-wave disclosure):** the MKT-057

   UX-001 (console only) siblings are in flight on the same base. This
