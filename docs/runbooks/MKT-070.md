## 2. Contract summary

### 2.1 What this module IS

The **deterministic, auditable planning layer** for a
product-marketing Growth Mission: it COMPOSES the cited authority
records into ONE plan version carrying every decision's evidence basis
as FK-anchored, scope-fenced citation links (the MKT-066
evaluation-record discipline). It decides; it never executes.

| Surface | Contract |
| --- | --- |
| `composeProductMarketingPlanCore` (pure, pm-plan-v1) | THE PLANNING CORE: a deterministic pure function over the record-derived `PlannerInput` snapshot (no clock, no randomness, no I/O). Emits the platform portfolio (tiered, score + weight share in bps summing to 10000), the metric plan (the frozen objective-family vocabulary, goal-wired BY REFERENCE), the content-strategy profile (pm-content-v1), the attribution plan (pm-attribution-v1) and the bounded experiment plan — each entry with rationale + citations. |
| `product_marketing_plans` + `product_marketing_plan_versions` (migration 060) | The AGENCY-SCOPED plan headers (ONE per mission) and the APPEND-ONLY version tail: every version carries actor + provenance + a REQUIRED reason + the deterministic input digest (idempotent replay converges; corrections are NEW versions). |
| The nine citation link tables | The FK-anchored same-scope evidence basis: cited product inputs / source facts / derived models / risk flags (same context), research insights (same session), platform-health evaluations (same client), experiment analyses + allocation recommendations (same client), content hypotheses (same client) — every anchored authority table read CHECK-ONLY by the scope-fence triggers. |
| `composeProductMarketingPlan` (module) | THE COMPOSITION COMMAND: resolves the mission (family-gated: only `product_marketing`), the cited /product-intelligence context, the optionally attached /research session (BY REFERENCE — the MKT-069 seam), the pursuit scope (workspace → client → agency), the pursuit client's health evaluations / experiment analyses / allocation recommendations / current content hypotheses — all READ-ONLY through the five frozen-row public contracts — runs the pure core, appends ONE immutable version + citation links, IDEMPOTENTLY (same digest → converge on the existing version). |

### 2.2 The product URL/code context changes the outcome (THE ACCEPTANCE)

The deterministic core derives product signals ONLY from the cited
/product-intelligence records: a declared
`source_repository`/`source_workspace` input is the **code-context
signal** (technical-authority posture: text/long-video classes scale,
`technical_authority` profile); evidence-backed content-worthy
features, market language, ICP hypotheses, value propositions and
commercial metrics scale the portfolio tiers and the metric-plan
targets (a consumer URL context → `broad_reach_visual`, short-video
weight). The integration test (a) proves it end-to-end: the SAME
mission machinery with two different cited product contexts composes
TWO different auditable plans — different portfolios, different metric
targets, different profiles — with each influencing record visible in
the citation links. Digest stability is pinned: the digest changes only
when the observable world changes.

### 2.3 Platform-health respect (the MKT-066 composition)

Portfolio candidates are the pursuit client's accounts WITH
platform-health evaluations on record (latest per account only — pinned
by unit test). A `restricted`, `publishing_blocked` or
`authorization_blocked` account is **EXCLUDED with the health verdict
evaluation cited** (never silently — the exclusion rationale names the
evaluation id, and the FK citation link resolves it); `degraded`,
`quota_limited`, `suspected_*` states deprioritize with the verdict
cited. Integration test (b) proves the FK-resolved citation exists on
the excluded entry.

### 2.4 Metrics, attribution, experiments (the v1.6 rules)

- **Metrics BY REFERENCE:** the frozen four-metric family vocabulary
  (`qualified_site_visits`, `attributable_conversions`,
  `engaged_platform_reach`, `content_engagement_rate` — terminal vs
  intermediate marked) wires the mission's EXISTING mapped goals as
  canonical goal ids. NO goal progress is ever re-stated or re-computed
  (the /goals authority stays sole; unit test (f) pins the by-reference
  wiring).
- **Attribution ≠ causality:** the plan declares WHAT will be measured
  (the measured surfaces) and HOW attribution will be computed (the
  closed method vocabulary over propagated attribution ids:
  last-touch / first-touch / linear multi-touch) — the
  attribution-is-not-causality disclosure ships on EVERY plan view.
- **Experiments as DATA:** the bounded next experiment (hypothesis,
  primary metric, arms, assignment, analysis method, stop criteria) is
  recorded DATA toward the Growth Operator's bounded delegation through
  the EXISTING /experiments authority — the planner creates NO
  experiment and owns NO workflow/execution lifecycle
  (boundedBy: 'growth-operator' + the disclosure on every view).
- **Evidence tier:** only evidence-backed derived models and verified
  research insights INFLUENCE decisions; unverified records are
  disclosed present-but-non-influencing (the §7 claim discipline — unit
  test (e)).

### 2.5 What it is NOT (the bounded scope)

NO second mission authority (the mission read model is consumed
READ-ONLY; /growth-missions stays sole). NO workflow/execution engine,
NO scheduler/timer/loop of ANY kind (boundary test greps the module for
setInterval/setTimeout/queue/loop vocabularies — zero). NO provider
calls (the platform mix composes from cited health evaluations, never
live provider traffic). NO goal-progress computation, NO experiment
creation, NO distribution dispatch, NO console surface (Worker C owns
console/**). The route surface is EXACTLY three GET/POST record routes
— no PUT/PATCH/DELETE anywhere (plan corrections are new versions).
